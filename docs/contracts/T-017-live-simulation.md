## Approved rules and first integration boundary

Continuous 60Hz simulation. Opening menu pauses; building does not. Test start full ring1, Flak12/slot0, relay6/slot0, energy one Flak price. Weapons auto-target/fire via WeaponRules. Kills bank energy once. Pressure/stats from T-016; existing enemies never receive later escalation. D-059 adds required pressure.max_active_machines=1000 positive_integer to testing data/schema. At capacity skip scheduled arrivals permanently, no deferred burst. No final cap claim.

Normal machines move inward at their own spawn speed, overlap, cannot pass intact wedges, and pass through broken/collapsed gaps. This first wall-free Phase 2 integration follows the current bearing radially to the first intact wedge inward, attacks its outer surface with continuous DPS, then advances after it breaks. Walls, angular detours, and the shared route field are integrated in Phase 3 after wall-edge rules; do not pretend this task implements wall funneling or change the planned scope. No Terrain, Tunneler, power, retake, repair, or abilities here.

Seven distinct broken wedges collapse that ring immediately, setting all its wedge HP to zero and removing all occupants/relay. No refunds or outer-ring cascade (D-020). A broken individual wedge suppresses its weapons as already implemented; total occupant destruction is on whole-ring collapse. Core begins at profile health.core_hp and takes continuous damage when no intact wedge remains inward on the machine's bearing. At core HP0 run ends; stop further gameplay updates/purchases. No restart/pause UI or end-screen style chosen here.

D-058 blocks whole-ring purchase when any living machine's authoritative polar band equals the proposed new ring. No energy spent on rejection. Existing requirements for inward intact wedges, relay slot and affordability still apply. No moving/removing enemies to enable expansion.

## State and public API

LiveSimulation extends RefCounted. static create(profile:BalanceProfile,ring_limit:int)->{ok,simulation:LiveSimulation or null,errors:PackedStringArray}; validates data and positive ring_limit, uses BuildingRules.create_default_testing_state. Public read-only-by-convention state:Dictionary (existing build state), core_hp:float, elapsed_seconds:float=0, ended:bool=false, cooldowns:Dictionary={}, last_events:Dictionary. pool:EntityPool is inspectable for tests, with no production mutation outside simulation. Store profile and ring_limit. No hidden capacity literal; pool constructed from profile max_active_machines. Advance uses supplied fixed step; clock belongs to scene integration.

func step(delta_seconds:float)->Dictionary {ok,errors,events}; only accept finite positive 1/60 step within 1e-12 seconds, no variable-step catchup. Ended steps succeed with empty events and no changes. Invalid input fails before mutation. Keep integer tick count and derive elapsed=ticks/60, avoiding accumulated drift. Tick order: admit due arrivals; move/attack existing machines in lifetime ID order; apply breaks/collapse immediately before processing next machine; if core dies stop remaining gameplay in that tick; otherwise call WeaponRules.step once, persist returned HP/cooldowns, release kills, bank energy_awarded exactly once. This stable technical order must be documented and covered. Fail invalid rule results clearly; valid maintained internal state must not produce partial error ticks.

New arrivals move only for time since their due time within this tick (normally zero at exact default boundaries); existing machines get full dt. At an intact surface, use any leftover movement time for DPS; never move farther than speed*dt or attack for more than leftover dt. If an attack breaks a wedge, movement resumes next tick (no damage carryover to another surface in same tick). Treat outer boundary contact as the outward polar band, using contact radius rather than cell-center snapping. Spawn positions at fixed bearing centers remain there during this radial phase. Use scalar radius=CORE_RADIUS+(ring-1+radial_fraction)*RING_WIDTH for positive rings, radial_fraction*CORE_RADIUS for core. Core outer surface radius=CORE_RADIUS. Convert radius back to polar with outward boundary ownership. No Cartesian authoritative state or position teleporting.

Existing build state retains contiguous HISTORICAL ring IDs even after collapse, for stable identifiers. Add optional ring record `collapsed:bool` (absent=false) and extend RingPurchaseRules.validate_state: collapsed rings require all12 wedges hp0, empty occupants, empty relay; max_hp/slot_count remain valid original values. Other records keep existing relay validation. This is a tombstone, not owned traversable structure. No repurchase/retake of tombstones in slice; next candidate stays historical rings.size()+1, and a broken latest ring blocks expansion as before. Existing WeaponRules loops already suppress hp0/empty occupants and need no changes. Preserve existing pre-collapse fixtures and validation tests.

func targets_snapshot()->Array[Dictionary]: lifetime-ID order, independent target records including copied PolarPosition, fields id,position,hp,damage_per_second,speed_ring_widths_per_second. func outer_owned_ring()->int: highest noncollapsed historical ring, or0. This value supplies spawn radius, not historical count.

func quote_expansion(relay_wedge:int,relay_slot:int)->Dictionary: existing RingPurchaseRules quote format; reject ended/occupied candidate then delegate. func purchase_ring(relay_wedge:int,relay_slot:int)->Dictionary {ok,state,errors}: revalidate via quote and existing purchase; on success replace internal state. func place_weapon(ring:int,wedge:int,slot:int,kind:StringName)->same: ended rejection then delegate and persist. Returned state must be an independent copy, so UI does not mutate live state accidentally. UI reads simulation.state, uses these methods only.

Events Dictionary always contains spawned_ids:Array[int],kill_ids:Array[int],broken_wedges:Array[Vector2i],collapsed_rings:Array[int],hits:Array[Dictionary],energy_awarded:number,core_lost:bool. IDs refer to EntityPool lifetime IDs. last_events replaced each step; no unbounded history. Expose counts of skipped arrivals for diagnostics (skipped_arrivals:int), not player UI. Release killed payloads after copying weapon results; no stale payload references retained.

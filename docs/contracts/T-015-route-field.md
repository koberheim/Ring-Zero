# T-015 - Shared polar route field

Owner: Sol. This is generic engine routing, not enemy behavior or wall placement. Kevin approved overlapping enemies, radial/angular neighbors, and refreshed routes before movement after structural changes (D-054). A shared field lets many enemies query one route computation. No delegation.

Own src/core/polar_route_field.gd, tests/core/test_polar_route_field.gd, docs/reviews/T-015.md, and corresponding generated .uid files. Read this brief and owned files only. Existing PolarGrid API: constructor ring_count:int; is_valid_cell(Vector2i)->bool; cell_neighbors(Vector2i)->Array[Vector2i]. Cell (0,0) is core; other cells (ring>=1,wedge1..12). Core neighbors all ring1 wedges. Other neighbors same-ring wedge +/-1 with wrap, inward same wedge (core from ring1), outward same wedge within grid count. No diagonals.

Class PolarRouteField extends RefCounted. Static build(grid:PolarGrid, cells:Array[Vector2i], edges:Array[Dictionary], goals:Array[Vector2i])->Dictionary {ok:bool,field:PolarRouteField or null,errors:PackedStringArray}.

Cells explicitly list traversable cells. Each edge is exactly {a:Vector2i,b:Vector2i,cost:number finite >0}, bidirectional. Both endpoints must be listed cells and legal grid neighbors; no self edges, missing endpoints, duplicate undirected pairs, malformed types, or unknown edge keys. Cell and goal lists must contain unique valid cells; every goal must be traversable. Empty cells/goals are valid and produce no routes. Null grid is invalid. No defaults for edge costs or implicit edges: gameplay supplies its chosen traversal costs/barriers later. Use local copied graph inputs; do not retain mutable caller dictionaries, arrays, or grid. Grid validates membership/adjacency only.

Queries: distance_for(cell:Vector2i)->float (INF if not reachable/listed); next_cell(cell:Vector2i)->Vector2i (sentinel (-1,-1) if unreachable; goal returns itself); goal_for(cell:Vector2i)->Vector2i (sentinel if unreachable). All distances are shortest summed edge costs to any goal. Compute with multi-source Dijkstra and a binary min-heap, not a per-enemy search. Strict positive costs prevent predecessor cycles. Equal exact distances resolve by lowest goal (ring then wedge), then lowest next cell (ring then wedge), independent of input enumeration. Do not approximate cost equality. Reject nonfinite accumulated distances clearly with no partial field. Goals always resolve to themselves at zero.

The built field is an immutable snapshot by convention. Structural changes require a new field; callers replace it before next movement. No wall legality, target selection, speed, spawn logic, movement interpolation, scene integration, or gameplay cap. Choosing caller-provided costs keeps this utility from silently choosing a gameplay path metric.

Done: tests cover core, angular seam, inner/outer neighbors, weighted detour, multiple goals and exact ties under shuffled inputs, unreachable/isolation, malformed inputs, old snapshot unchanged after rebuild, and following next cells reaching the reported goal without cycles with summed cost equal to reported distance.

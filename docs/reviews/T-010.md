# T-010 delivery for Astra review

Implemented independent startup, whole-ring transactions, weapon placement, and automatic supplied-target combat. No scene or integration changes.

- `RingPurchaseRules` validates profile snapshots and complete contiguous state, computes grants/cost/HP/slots from profile data, validates explicit starter locations/counts, copies successful states, and returns no partial state on failure. Broken wedges are legitimate snapshots but block inward-ring expansion. Partial HP remains eligible. Each ring requires exactly one relay with matching slot/reference.
- `BuildingRules` exposes the default approved startup, slot geometry/selection, and atomic Flak/Mass Driver purchases. Default setup fails with an explicit-placement instruction if counts differ from one ring/one Flak/one relay. Relay is a normal occupied slot included through ring purchase.
- Per Astra's API amendment, eligible quotes return their price even when funds are insufficient, with `quote.affordable`. Purchase recomputes the quote and checks affordability before copying/deducting.
- `WeaponRules` clones targets and their PolarPosition objects, orders weapons by ring/wedge/slot, chooses nearest targets with exact-distance ID ties, uses each slot's outward radial arc, applies actual HP removed, and awards one reward on each live-to-dead transition. Profile arcs/ranges/damage/cycles/caps drive combat. Stale well-formed cooldowns are removed; malformed inputs fail with empty collections and zero energy.
- Added required `mass_driver.arc_degrees` schema field and 360.0 testing value; updated balance documentation and acceptance checks.

Numeric tolerance: range boundaries use 0.00001 world units and arc boundaries 0.00001 radians. Cooldown subtraction residuals at or below 0.000000000001 seconds snap to zero, preventing an extra fixed-step delay after 15 Flak ticks or 120 Mass Driver ticks. At most one volley per call; empty target sets leave a ready weapon ready.

## Profile API and crash boundary

`src/core/profile_store.gd` exposes instance `load_profile(path)`, `save_profile(profile,path)`, `begin_run(profile)`, `settle_run(profile,run_id,amount)`, `purchase(profile,id,cost,upgrade_level=-1)`, and explicit `recover_profile(path)`. Default path is `user://profile.json`; tests inject unique workspace paths. Static `defaults()` and `validate()` support controller settings candidates. Results contain `{ok,profile,errors,recovered}`; begin additionally returns `run_id`. Returned dictionaries are independent copies.

The contract's version1 schema adds two approved optional fields, normalized transparently when absent: `revision:0` and `settled_run_amounts:{}`. Revision compare-and-swap rejects stale candidates; successful saves increment and return revision, so controllers must always adopt `saved.profile`. Exclusive directory creation at `path + '.lock'` serializes writers around disk validation and commit. Owner metadata records the process ID. Existing locks fail promptly with `lock_recovery` (`busy`, `stale`, `unknown`) and `lock_owner_pid` fields for UI recovery. `release_stale_lock(path)` only removes a lock whose recorded process is no longer running. Separate `force_release_unknown_lock(path)` supports an explicit close-all-instances warning for missing/invalid owner metadata; it cannot remove a known live owner's lock. Recovery touches no profile bytes and stops no process. PID reuse conservatively counts as busy. Final follow-up PID46384 passed59 checks with zero failures, including dead/live/unknown lock recovery and future-version plus new-schema-field preservation.

Run IDs are canonical decimal strings allocated from a monotonic counter. Counter, revision and currency are bounded to JSON's exact integer range, 2^53-1; overflow fails before mutation. A begin candidate must save before play. Beginning again abandons an existing pending ID. Only the current pending ID can receive credit; settlement stores amount and receipt together, clears pending, and preserves a bounded history of128 receipts. Retained duplicate amounts must agree; conflicting repeats fail. Pruned/abandoned allocated IDs are harmless no-ops and never earn again. Future or malformed IDs fail. Practice/abandoned/error reward policy and catalogue eligibility/prices remain RunRules/controller responsibilities; the generic store validates identifiers, costs, sequential upgrade levels1–3 and funds.

No mid-run resume exists. A crash before a completed result is persisted is treated as abandonment and receives no reward. Atomic reward/receipt storage provides idempotent retries after commit; it does not promise recovery of an unpersisted completion.

## Disk safety

Public validation rejects missing/unknown fields, unsupported versions, malformed collections/IDs/receipt order, invalid settings, nonfinite/fractional numeric state and overflow. JSON integral numbers normalize to integers. Settings allow scales1.0/1.15/1.3. Invalid candidates cause no filesystem mutation.

Save obtains the writer lock, validates the current disk revision, writes/flushed/closes a sibling temporary file, reopens and validates it, preserves the valid primary as backup, then renames the temporary file into place. A failed final rename restores the previous primary; if rollback itself fails, the error identifies the valid backup. The backup protocol has a recoverable primary-missing interval, not an unsupported claim of power-loss durability.

Load prefers valid primary. Corrupt primary can return valid backup with `recovered=true` without overwriting anything. Normal save refuses corrupt or incompatible existing primary. Explicit recovery quarantines corrupt primary, restores validated backup and increments revision. Future versions never silently downgrade through an older backup. Missing primary with backup recovers; orphan uncommitted temporary files require explicit recovery rather than guessing reward credit. Missing profile returns defaults without disk writes.

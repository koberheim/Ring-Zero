# T-015 — shared polar route field

Owner: Sol. Date: 2026-09-06. Status: implemented and tested; awaiting Astra source/test review.

`PolarRouteField.build()` validates the supplied traversable cells, bidirectional neighbor edges with explicit positive costs, and goals. It computes one multi-source Dijkstra field with a binary min-heap. Queries read stored distance, next cell, and goal in expected constant time. No enemy-specific search, path metric default, gameplay barrier rule, or movement integration was introduced.

The field stores only its resulting dictionaries of value-type cell coordinates and distances. It retains no caller grid, input arrays, or edge dictionaries. Structural changes require a new field, which callers must replace before movement. Unreachable/unlisted cells return infinite distance and sentinel `(-1,-1)`; goals point to themselves at zero. Equal distances use exact floating-point equality, then lowest goal `(ring,wedge)`, then lowest next cell `(ring,wedge)`, independent of enumeration order. Edge costs are converted to Godot's floating-point representation for accumulation.

Validation rejects null grids, duplicate/invalid cells and goals, unlisted goals, malformed/unknown edge keys or types, nonpositive/nonfinite costs, self edges, missing endpoints, illegal neighbors, and duplicate undirected pairs. A reachable addition that overflows returns a diagnostic and null field. With Astra's explicit numeric-guard approval, a reachable positive addition that fails to strictly increase the current finite distance also returns a precision diagnostic and null field: without this representability requirement, rounded-away costs could produce equal-distance predecessor cycles despite mathematically positive costs. This compares the candidate sum with the distance being extended, not with the destination's existing shorter distance, so ordinary back edges remain valid. Empty graphs and goal sets are supported.

## Focused evidence

Godot 4.7.2 stable official `ed1daf0bf`: `polar_route_field: PASS`, exit 0; test/benchmark process approximately 0.653 seconds including startup. Import exit 0, approximately 2.248 seconds. The existing Windows root certificate-store diagnostic appeared at startup, with no test failure.

Tests cover core routing, angular 12-to-1 seam, inward/outward radial routing, a cheaper weighted detour, isolated/unlisted cells, empty graphs/goals, immutable old snapshots after rebuilding and clearing caller containers, two-goal ties and next-cell ties across eight seeded permutations, goal self-resolution, and a real `1e-10` cost difference that must not become an approximate tie. Malformed input checks cover the rejection cases above, including reverse duplicate edges, accumulated overflow and rounded-away positive cost.

An independent Floyd–Warshall all-pairs implementation checks all 25 cells of a two-ring graph with varied integer costs and three goals. Every production distance and selected goal matches the independent reference. Every next-cell chain reaches the reported goal without cycles, follows supplied edges, and has summed cost exactly equal to the reported distance. Integer fixture costs intentionally make these independent sum comparisons exact; arbitrary noninteger sums remain subject to ordinary floating-point rounding.

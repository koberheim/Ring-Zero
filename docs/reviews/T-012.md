## Implementation and validation

`EntityPool` preallocates one dictionary per record, uses a free-slot stack and dictionary ID lookup, clears released records, and issues monotonically increasing lifetime IDs. Its maximum signed 64-bit ID is usable once, after which spawning diagnoses exhaustion rather than wrapping. Incoming top-level dictionaries are copied; mutable values remain shared. Live payload references expire at release. `active_ids()` returns an independent ascending-ID snapshot (sorting cost included in the iteration benchmark). `allocated_record_count` exposes stable record count for inspection; neither this nor slot reuse claims allocation-free dictionary operations.

`FixedStepClock` accumulates fractional elapsed time and delivers equal `1/tick_hz` steps. The documented boundary allowance is `1e-12` of one step; tolerated rounding deficits clamp to zero. Paused advances do not accumulate time, while the pre-pause fractional remainder survives. If the tick callback pauses the clock, delivery stops at that tick and remaining wall time in the current advance is discarded as paused time. Invalid rates, callbacks, and negative/nonfinite deltas diagnose and remain inert. A positive finite rate whose reciprocal overflows is also diagnosed because its step cannot be represented. There is no catch-up cap or dropped-time policy; large deltas can consequently take substantial time to process. Callback lifetime/reentrancy beyond pausing and astronomically large float/int ranges are not exercised by this focused suite.

Final focused run: `simulation_foundation: PASS`, process exit 0, approximately 0.359 seconds including startup. It checks zero/full/negative capacity, top-level isolation, shared mutable values, live lookup, clearing and identity reuse of the payload dictionary, stale IDs, independent ordered snapshots, 1,000 churn cycles with stable two-record storage, final-ID exhaustion, six equal partitions of one second (1/3/7/60/144/1,000 calls), unequal partitions, callback count/step size, elapsed time, pause/resume, callback-triggered pause with no later catch-up, and invalid construction/input. Diagnostic ERROR messages for intentional invalid inputs are expected. The Windows root certificate-store diagnostic also appeared at startup; execution and assertions completed.

## Benchmark fixture and method

Godot 4.7.2 stable official `ed1daf0bf`, headless script execution; rendering absent. No graphical capture ran concurrently (coordinator confirmation). CPU/GPU CIM inventory was denied by the environment. CPU identification unavailable. The coordinator's separate prior renderer observation identified NVIDIA GeForce RTX 4080; this headless benchmark does not measure its performance.

Each capacity uses three warmups and ten measured samples. `Time.get_ticks_usec()` measures whole operations, excluding process startup. Median averages the middle two observations; p90 uses nearest rank; maximum is also reported. Each pool is constructed outside the measured loop. Spawn fills an empty pool, iteration obtains/sorts an ID snapshot and reads all payloads, release consumes a preobtained snapshot, and reuse immediately refills the released slots. Subsequent spawn samples also reuse storage. Input dictionary construction is included in spawn/reuse. Fixture setup, cleanup after reuse, verification, and printing are excluded from timings. This is not a memory-allocation profiler.

Combat fixture loads `data/balance/testing.json`, creates the default state, sets fixture energy to 1,000, and arms ring 1 slot 0 in wedges 1â€“11 except relay wedge 6 with Flak. Starter Flak in wedge 12 remains, for 11 Flak weapons and one relay. Supplied targets use lifetime IDs 0 through Nâˆ’1, band 2, evenly cycled wedges 1â€“12, radial/angular fractions 0.5, and HP `1e12`. Fractions intentionally coincide within each wedge, so this is a dense, reproducible distribution rather than a spatially varied live crowd. Each call uses empty cooldowns and delta `1/60`, with the original targets retained. All target IDs and HP are checked after every call; no kills or pool growth occurred. The first measured volley at each size produced 55 hit records. Returned combat state is not carried forward: this measures the current complete ready-volley function, including validation/copying/target search/damage-result work, rather than an isolated search function or realistic sustained firing cadence.

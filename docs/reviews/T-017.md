# T-017 first live normal-machine simulation

Implemented the independent `LiveSimulation` service, required positive-integer `pressure.max_active_machines: 1000`, and strict collapsed-ring tombstones in `RingPurchaseRules`. Only owned gameplay/data/test/documentation files changed; presentation and core implementations are untouched.

`create` validates and copies the profile, initializes approved startup, core HP, and the configured pool. Public purchase methods reject ended runs, enforce occupied-candidate-band expansion, and return independent state copies. Target snapshots clone polar positions in lifetime-ID order. Stepping requires a positive 1/60 second within 1e-12; elapsed time comes from an integer tick count. Not stepping is the pause mechanism; placing buildings introduces no pause.

The stable tick order is: compute and admit due arrivals up to free capacity; process machines in lifetime-ID order; immediately apply each break/collapse before the next machine; stop remaining gameplay if the core dies; otherwise run automatic weapons once, persist returned HP/cooldowns, release killed payloads, and bank energy once. Newly admitted machines receive only time since their own due time within the tick. Skipped arrivals are counted and discarded permanently, with no deferred burst.

Radial movement uses scalar radius and authoritative PolarPosition. Machines stop at the first intact inward wedge surface, spending only remaining travel time on continuous DPS. They overlap, pass through gaps, and resume moving on the tick after their own wedge-breaking attack. A later lifetime ID sees an earlier break in the same tick. Contact uses the outward polar band. Seven configured distinct breaks collapse a ring, clear occupants/relay, preserve historical IDs and dimensions, issue no refund, and do not cascade into outer rings. Core loss ends further gameplay and purchasing.

Gameplay updates are staged before commit. Invalid timing/profile/state/arrival descriptors fail before admissions. Per Astra's explicit approval, unexpected downstream failure releases only tentative admissions, preserves state/time/core/cooldowns/skipped counters/events and existing payloads, and may consume their monotonic lifetime IDs. Those IDs are never reused. A malformed-cooldown fixture verifies this rollback and the next admission's advanced ID. No pool transaction/core API changes were needed.

Execution used workspace cache/log locations and tracked hidden process objects. A finite Process.WaitForExit replaces the unbounded Start-Process -Wait switch, retaining the exact child PID for timeout cleanup:

```powershell
$env:APPDATA = Join-Path (Get-Location) '.godot/appdata'
$env:LOCALAPPDATA = Join-Path (Get-Location) '.godot/localappdata'
# Import used --editor --import --log-file .godot/t-017-import.log, timeout30000.
foreach ($suiteName in @('balance_profile','building_rules','weapon_rules','machine_spawn_rules','live_simulation')) {
  $suiteArguments = '--headless --path . --script tests/gameplay/test_' + $suiteName + '.gd --log-file .godot/t-017-' + $suiteName + '-tests.log'
  $suiteProcess = Start-Process -FilePath 'E:/Godot/Godot_v4.7.2-stable_win64.exe' -ArgumentList $suiteArguments -PassThru -WindowStyle Hidden
  Write-Output ($suiteName + ' PID=' + $suiteProcess.Id)
  if (-not $suiteProcess.WaitForExit(15000)) { Stop-Process -Id $suiteProcess.Id; throw 'Tracked test timed out' }
  Write-Output ('Exit=' + $suiteProcess.ExitCode)
}
```

Final logs are `.godot/t-017-<suite>-tests.log`; no final script parse/runtime errors occurred. The environment root-certificate-store diagnostic persists. No T-017 child process timed out or became untracked.

# T-048 — solar ability gameplay delivery

Source/tests/data frozen for Astra review; exclusive Godot window released. No core, presentation, terrain, existing balance-value, or recorded-baseline changes.

## API and behavior

`AbilityRules.cast(profile, targets, cooldowns, kind, aim)` is pure. Kinds are `&"focused_flare"` and `&"emp_burst"`. Results contain `ok`, `errors`, `targets`, `cooldowns`, `hits`, `kill_ids`, and `energy_awarded` (always zero). Hits have exactly `{ability_id: StringName, target_id: int, damage: float}`. Target/hit/kill order follows supplied target order. Known mutable position metadata and status arrays are independently copied.

Flare uses the clicked bearing from the core and a range-limited angular sector. Zero-radius aim is invalid. EMP uses a circle centered at the clicked point, including a valid core-origin point, with no aiming-distance restriction. Both ignore dead or untargetable enemies. EMP refreshes surviving targets' stun with the maximum of existing/new duration. Valid empty casts consume cooldown; malformed/cooling/invalid casts fail atomically. Cancellation remains UI-only with no command invocation.

Range/sector calculations use double-precision polar radius and bearing matching PolarGrid, not float32 Vector2 coordinates. EMP distance uses squared radial difference plus the half-angle sine term, avoiding subtraction of large rounded Cartesian coordinates. Existing weapon boundary tolerance is retained. Sol's review identified the ring-50/radial-0.1 rounding case; explicit Flare and local EMP boundary regressions now pass with outside controls. Core-band radius/bearing mapping is also covered.

`LiveSimulation` adds `ability_cooldowns`, independent `abilities_snapshot()`, and `cast_ability(kind, aim) -> {ok, errors, events}`. Commands validate structural/live target state and stage through the pure helper. A local navigation graph validates traversability/lifecycle without replacing or changing the live cache. Successful casts commit only HP/stun, ability cooldowns and releases. They leave energy, structural state, positions, navigation/waypoints, weapon cooldowns and elapsed time untouched. Their event payload uses the existing events shape and remains separate from `last_events`. Command kills are released immediately and never repeated as next-tick kills. Presentation must count command kills once separately.

Each successful fixed tick stages ability cooldown subtraction and commits it with gameplay state, using existing cooldown roundoff tolerance. Failed ticks and ended no-op ticks leave ability cooldowns unchanged. New runs start ready with an empty dictionary; missing keys mean zero remaining cooldown. Existing stale waypoints for command-killed IDs remain untouched by the cast and are cleaned by the normal successful tick cleanup.

## Rendered 1,000-machine measurement

Final batched frame interval is **16.655 ms median / 16.765 ms p90**, simulation CPU **10.259 / 10.512 ms per frame**, with all 1000 markers retained. Draw-submission CPU fell to **0.901 / 0.925 ms**. The before measurements below are retained as labeled review evidence; they are superseded by the final comparison table.

The fixture keeps max_active_machines at the approved 1000, disables scheduled arrivals and uses machine/wedge HP 1e12 with DPS 0.01. It grants 10000 energy only for setup, builds Flak on every ring-1 wedge except Relay wedge 6 (11 Flak including the starter at 12), and inserts 1000 machines round-robin across the 12 wedge centers at the ring-1 surface (ring 2 / radial 0 / angular 0.5), each HP 1e12, DPS 0.01, speed 1. All 1000 remain active throughout sampling and targeting runs normally.

After a three-second wall-clock warmup, 120 full-scene frames were sampled, with rendering and the normal fixed-step accumulator enabled. Simulation CPU sums time inside simulation.step calls per rendered frame, including multiple catchup ticks; it excludes snapshot refresh, UI/draw preparation and rendering. Frame intervals are measured between process_frame signals, not GPU timings.

Original measurement, retained exactly as first reported (rounded-middle percentile helper):

| --- | ---: | ---: |
| Full frame interval | **37.698 ms** | **46.556 ms** |
| Simulation CPU per frame | **22.619 ms** | **31.269 ms** |

The additional before profile isolated 6.919 ms median draw-submission cost, versus 2.422 ms snapshot/refresh. That justified the presentation-only batching correction. Identical repeated quote scans were cheap (0.036 ms), so the single-result reuse is minor. Batching moves polar conversion/instance upload into snapshot refresh and removes 1000 individual draw submissions. It reduces frame cost enough that the fixed clock usually runs one tick per frame instead of two or three; the lower simulation CPU per frame reflects fewer accumulated catchup ticks, not gameplay changes or reduced simulation rate.

Renderer: `gl_compatibility`, OpenGL 3.3, NVIDIA GeForce RTX 4080, driver 610.88. Every comparison retains VSync mode 1 (enabled), Engine.max_fps 0 (uncapped), all 1000 markers, 11 Flak, the same durable-contact fixture, three-second warmup and 120 frames. The residual interval is frame interval minus measured simulation, sync and draw CPU for each sample.

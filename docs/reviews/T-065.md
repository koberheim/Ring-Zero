## Shared API

`RunRules.catalogue()` returns independent dictionaries `doctrines`, `loadouts`, `mutators`, `unlocks`, `upgrades`, `reference`. IDs are Strings. Every entry has `label` and `description`. Unlock entries have integer `cost`, `category` (`build`, `ability`, `loadout`) and String `target`. Unlock IDs: emp_node, tractor_lane, occlusion_screen, lance_emitter, focused_flare, bulwark, battery. Upgrade IDs core_hp, wedge_hp, starting_energy have integer max_level and integer costs array; next price is costs[current_level]. Remaining entry modifier metadata is editable in campaign.json.

`default_choices()` returns `{doctrine:"conservator",loadout:"balanced",mutators:[]}`. `prepare(base,choices,progress,practice=false)` returns the contract fields plus `starting_energy:int` and `practice:bool`. Mutator IDs are normalized into sorted order in an independent choices copy; caller inputs remain unchanged. Invalid IDs, duplicate choices/unlocks, invalid levels, locked loadouts, malformed catalogue or unusable computed values return `ok:false`, null profile and actionable errors. All doctrine/mutator/upgrade effects resolve into a new validated BalanceProfile. The editable `economy.repair_discount` defaults to 1 and gives repair its own modifier without discounting expansion. Discounted campaign repair/Reclaim costs round upward; unchanged default pure prices retain historical behavior.

`create_run` adds the simulation, enables all seven enemy kinds, applies the explicit starter replacement/wall and paid loadout cost, and installs gameplay-side allowed build/ability guards. Prepared build modes include structural action IDs expand/wall/armor/repair_node/repair/reclaim/rebuild_relay. Practice grants full catalogue access but not extra progression; its reward multiplier is zero and the simulation forces practice summaries, preventing an accidentally requested defeat summary from becoming eligible. Existing direct LiveSimulation.create defaults and testing scenes retain full testing access.

`LiveSimulation.run_summary(outcome="defeat")` returns a fresh `{outcome,elapsed_seconds,kills,highest_ring,relay_rebuilds}` dictionary. It has no reward calculation or persistence dependency. Successful tick/cast commits increment authoritative total kills; ability kills still award zero energy. Successful ring purchase updates the historical maximum and successful Rebuild Relay increments its count. Failed commands/ticks leave totals unchanged. Supported result outcomes are validated by `RunRules.reward`: defeat, abandoned, error, practice. Reward validation rejects malformed fields, nonfinite values and amounts beyond exactly representable safe integer accounting. Reward result is `{ok,errors,amount:int,breakdown}`; ineligible outcomes return amount0. Eligible breakdown keys are survival,kills,rings,survive_300,kills_250,rebuild_relay,subtotal,multiplier,eligible. The selected multiplier is applied once, then floored. Persistence and run-ID settlement belong to ProfileStore/controller, not this gameplay layer.

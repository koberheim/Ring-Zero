# T-020 — constant-speed polar motion

Owner: Sol. Date: 2026-09-06. Status: implemented; focused tests pass; ready for Astra review before gameplay consumption.

`PolarMotion.advance()` interpolates one caller-supplied radial segment or shortest angular arc using double-precision scalar radius and bearing. It uses `PolarGrid.CORE_RADIUS` and `RING_WIDTH`, retains polar coordinates as the authoritative result, and chooses no route or gameplay action. Runtime work is constant with respect to crossed cells.

The helper validates outside-core positions, finite fractions in `[0,1)`, positive finite speed, and nonnegative finite delta. Endpoints differing in both radius and bearing are rejected. Radius equality permits at most `1e-8` world units; bearing equality permits at most `1e-12` turns. Reconstruction resolves exact boundaries with outward band ownership and clockwise wedge ownership, applying only `1e-10` world units / `1e-14` turns of boundary roundoff correction. Angular differences are computed directly from wedge and fractional differences before absolute-bearing conversion, preserving exact clockwise half-turn ties even for fractional positions.

Success returns an independent `PolarPosition`, consumed time, and whether the target was reached. Reaching a target returns an exact clone of that target and only `distance/speed` time, leaving any residual time to the caller. Identical endpoints consume zero time; zero delta clones the current position for a distinct valid segment. Inputs are never mutated.

Numeric failures return `{ok:false,position:null,time_used:0,reached:false,errors:[...]}`. Guards cover nonfinite duration, underflowed travel, unrepresentable progress, and band IDs beyond exact floating-point integer representation. Endpoint radius conversion must round-trip the supplied band and fraction within the documented radial tolerance, otherwise it diagnoses precision loss rather than silently discarding the fraction. Reconstructed band IDs are checked before integer conversion; no signed overflow or cell-by-cell traversal occurs. These guards are conservative limits on numerical representation, not gameplay limits on ring count or speed.

## API and ordering

`RunRecorder` is independent of gameplay rules. Static `make_metadata(run_id,base_profile,effective_profile,choices,progress,practice=false)` accepts balance snapshots, stores choices and only progress unlocks/upgrades/revision (not currency, receipt history or unrelated user data), computes an effective-profile content fingerprint and includes engine/build identity. Seed is explicitly null and randomness `none` for current deterministic gameplay. `default_path(run_id)` creates a unique local `user://runs/*.jsonl` path; tests use unique `.godot` paths.

Instance API: `start(path,metadata)`, `append_command(tick,action,args,result_ok,command_errors=[])`, `marker(tick,event,data={})`, `finish(tick,outcome,summary)` and copied `snapshot()`. Static `load_trace(path)` validates ordered records and reports `complete` only after a valid end row. Results use `{ok,errors}`; loader additionally returns trace/complete. Markers support pause/resume/error/abandon/diagnostic. Commands include failed attempts, scalar polar aim and monotonic sequence for same-tick order. The tick is the exact committed `LiveSimulation._ticks` before dispatch, explicitly approved by root for diagnostics; it is never reconstructed from floating elapsed time.

JSON lines use full-precision float encoding, tested bit-for-bit for difficult polar fractions. Content fingerprinting canonicalizes whole JSON doubles to integers and sorts keys, so parsed numeric types do not falsely change profile identity. Records preserve scalar floats themselves. Existing files are never overwritten; paths are confined to local user runs or workspace test cache, files bounded to16MiB and50000 records, values finite/JSON-safe with recursion/string/collection bounds. Each command append flushes/closes; no per-tick disk write occurs. Any active recording validation/I/O failure is sticky, prevents a later successful finish and leaves the valid prefix incomplete. The UI must surface that warning while authoritative gameplay continues. Truncated final lines, invalid order, malformed error arrays and rows after end are rejected. No cryptographic authenticity or hostile tamper protection is claimed.

Luna hook contract: start after durable ProfileStore begin save and before gameplay; record each real live command once at its wrapper, avoiding duplicate records through weapon fallback; record ability selection only when an actual cast is attempted. Record pause/resume and outcome/error markers. Normal-run command traces are the reproduction target. Tutorial code mutates isolated practice fixtures; those mutations must be explicitly marked/recorded by its hooks or the trace remains explanatory practice diagnostics, not a claim of complete deterministic tutorial replay.

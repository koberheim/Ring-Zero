# T-043 — gameplay contract corrections

Delivered for Astra acceptance. Source, tests and data are frozen; the exclusive Godot window is released. No core/presentation changes or recorded-baseline updates.

## Corrections

- Public live snapshots independently clone assimilation arrays. Private staging keeps these arrays read-only and replaces them at commit. Both weapon ownership paths and live preflight reject malformed optional status fields: stun must be finite numeric/nonnegative; assimilation must be an Array of finite numeric/nonnegative expiries. Booleans, strings, nulls, NaN and infinities fail through structured results, including when no weapon is ready or a target is untargetable. Existing/admission status validation precedes pool admission and navigation mutation.
- EMP hits every living targetable eligible target on its own ring within radius. Lance hits every eligible same-column target outward from its firing radius, using the existing world-distance tolerance. Neither truncates by legacy `max_targets`; that field remains schema-valid for compatibility. Other weapon caps, power allocation, ordering, range/cooldowns and Point Defense's exact-cell rule are retained.
- Stun subtraction uses the existing cooldown epsilon so a 1.5-second stun ends after exactly 90 frozen fixed ticks. Movement resumes on tick 91. Current whole-tick freeze semantics are retained; no partial-tick resumption was introduced.
- D-094 repair quotes and mutations share the same live occupancy guard. A zero-HP wedge containing a living machine cannot be repaired; rejection spends nothing. Dead machines do not block repair, and dead normal records with valid positions do not invalidate the subsequently restored cell. Damaged but intact wedges remain repairable while a surfaced Tunneler attacks them. Pure RingPurchaseRules is unchanged.
- Additional authorized scope moves the unchanged assimilation constants into required validated profile fields: `assimilation.bonus_per_stack = 0.05`, `max_stacks = 10`, `stack_seconds = 15.0`. Actual damage, grant capacity and expiry use overrides. Computed multiplier/expiry overflow fails before admissions. The private static multiplier helper now takes the profile as its third argument. No trigger, recipient, decay-shape or default tuning change was made.
- Reproduced finite-input armor addition overflow; BuildingRules now rejects nonfinite resulting current/max HP before mutation or spending.

Changed files: `src/gameplay/live_simulation.gd`, `weapon_rules.gd`, `building_rules.gd`, `balance_profile.gd`; `data/balance/testing.json`; corresponding live/weapon/building/balance gameplay tests; `docs/balance-data.md`; this report. Building/profile/data ownership expansion was explicitly authorized by Astra after the initial corrections.

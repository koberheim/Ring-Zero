# Baseline digests

`t-023-sustained-cost-digests.bin` holds the exact per-tick full-state/event/waypoint SHA-256 digests that `tests/gameplay/test_live_simulation.gd`'s `--cost-review` mode compares against, for the sealed and sustained-ring3-angular 1,000-machine fixtures. It is tracked here (A5, Phase 6) instead of `.godot/` because that directory is gitignored and gets deleted/regenerated per machine — a baseline that only exists there is not reproducible from a clean copy.

**Provenance:** recorded during T-023 (2026-09-06/07), against the `sustained_sealed` / `sustained_ring3_angular` fixtures in `test_live_simulation.gd::_cost_fixture` at that time (1,000 machines, HP 1e8, standard-machine DPS 1.0, spawning disabled, 123 measured ticks per mode). Relocated without regeneration during Phase 6 (T-032); byte-identical to the original `.godot/t-023-baseline-digests.bin`.

**Re-recorded 2026-09-07 (T-039, D-021 assimilation):** every machine payload gained a new `assimilation_stacks` field, so `targets_snapshot()` — part of what the digest hashes — changed shape for every machine on every tick, regardless of gameplay behavior (the field is empty/no-op for these no-destruction fixtures). Confirmed via `--cost-review` without `--record-cost-baseline` first: all 246 digests mismatched uniformly, consistent with a shape change rather than a behavior change. Re-recorded with `--record-cost-baseline` after that check; the fixture, tick count and all other conditions are unchanged.

**Re-recorded 2026-09-07 (T-040, D-088 EMP Node stun):** every machine payload gained a new `stun_remaining` field (D-088's per-machine status-effect state), so `targets_snapshot()` changed shape for every machine on every tick again, regardless of gameplay behavior (the field is 0.0/no-op for these fixtures — no EMP Node is placed in them). Confirmed via `--cost-review` without `--record-cost-baseline` first: all 246 digests mismatched uniformly. Re-recorded with `--record-cost-baseline` after that check, then reran clean (785/0) to confirm stability.

**Re-recorded 2026-09-07 (T-055, D-104 relay decoupling + D-105 slot density):** the ring record's `relay` field changed shape (from `{wedge, slot}` to `{"active": true}`/`{}`), and `scaling.slots_per_wedge_per_ring` rose 1→2, both changing `sim.state` for every tick. Confirmed via `--cost-review` without `--record-cost-baseline` first: all 246 digests mismatched uniformly. Before re-recording, investigated a real change buried in that uniform mismatch: the `sustained_ring3_angular` fixture's hit-count pattern shifted (from occasional 30/35-hit volleys to regular 15-hit volleys every ~15 ticks). Isolated the cause by temporarily reverting only `slots_per_wedge_per_ring` to 1 (keeping the relay change) and confirming the hit pattern reproduced exactly — the fixture places Flak at a literal `slot=1`, and `BuildingRules.slot_position` computes a weapon's bearing from `(slot+0.5)/slot_count`; doubling ring 3's slot count moves that Flak's aim off the old wedge-center bearing, which is a real and correct consequence of D-105, not a bug. Re-recorded with `--record-cost-baseline` after confirming this, then reran clean (785/0) to confirm stability.

**Re-recorded 2026-09-07 (T-059, D-108 Sapper relay-hp pool):** every non-collapsed ring record gained two new sibling fields, `relay_hp`/`relay_max_hp` (D-108's Sapper attack target, separate from any wedge's HP), so `sim.state` changed shape for every tick regardless of gameplay behavior (no Sapper is enabled in these fixtures). Confirmed via `--cost-review` without `--record-cost-baseline` first: all 246 digests mismatched uniformly, with zero non-digest (count/timing) mismatches — a pure shape change. Re-recorded with `--record-cost-baseline` after that check, then reran clean (785/0) to confirm stability.

**Do not regenerate this file silently as a side effect of changing the code it's meant to check.** A digest mismatch means either a real behavior change (investigate before touching the baseline) or a deliberate, reviewed fixture/rule change. To intentionally record a new baseline after a reviewed change, rerun with `--record-cost-baseline` and note in the relevant task/decision record *why* the baseline moved and what changed.
